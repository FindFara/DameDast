# دمِ دست چگونه کار می‌کند؟

برنامه سه قسمت دارد: افزونه مرورگر برای خواندن اطلاعاتی که خودت باز کرده‌ای، PWA برای نمایش و مدیریت مالی و سرور برای نگهداری و همگام‌سازی بین دستگاه‌ها.

## داده از سایت مالی تا گوشی

1. ورود به دیجی‌پی، اسنپ‌پی، ایزی‌تریدر، آگاه یا نوبیتکس در خود سایت انجام می‌شود. افزونه فقط با کلیک تو جدول‌های بارگذاری‌شده را می‌خواند.
2. ستون‌ها را مرور می‌کنی. نام حساب و فهرست، نوع دارایی و واحد مبلغ را تعیین می‌کنی. داده خام صفحه قبل از تأیید وارد دیتابیس سرور نمی‌شود.
3. افزونه مبلغ‌ها را به تومان تبدیل می‌کند؛ عدد سهم و رمزارز اعشاری باقی می‌ماند. تاریخ شمسی به تاریخ ISO تبدیل می‌شود تا مقایسه و یادآوری ممکن باشد؛ نمایش فارسی همچنان شمسی است.
4. اطلاعات تأییدشده در داشبورد افزونه ذخیره می‌شوند. انتقال به PWA با مجوز همان دامنه و تأیید واردکردن در PWA انجام می‌شود. خروجی و ورود JSON هم در دسترس است.
5. PWA ابتدا نسخه محلی را ذخیره می‌کند و تغییر را در صف می‌گذارد. اگر وارد حساب شده باشی و اینترنت برقرار باشد، تغییر به سرور ارسال می‌شود.
6. گوشی، با همان نشانی و همان حساب، نسخه سرور را می‌گیرد. همگام‌سازی هنگام بازبودن برنامه هر ۳۰ ثانیه و با دکمه «همگام‌سازی» انجام می‌شود. برنامه بسته به‌طور مداوم داده مالی سایت‌ها را نمی‌خواند.

## دقیقاً کجا ذخیره می‌شود؟

| بخش | فناوری | داده |
| --- | --- | --- |
| افزونه | chrome.storage.session | جدول خام موقت؛ پس از ذخیره موفق پاک می‌شود |
| افزونه | chrome.storage.local | فهرست‌های تأییدشده و نشانی مقصد |
| PWA روی گوشی یا دسکتاپ | IndexedDB، دیتابیس poolo-v1، فروشگاه spaces | آخرین نسخه دریافت‌شده و صف تغییرات ارسال‌نشده |
| ترجیحات PWA | localStorage | زبان، تم و شناسه آخرین حساب برنامه؛ شامل رمز سرویس‌های مالی نیست |
| سرور شخصی ASP.NET Core | EF Core 10 و SQLite | تمام داده‌های مالی و اطلاعات تجمیعِ کاربر واردشده |
| نسخه میزبانی‌شده ارائه‌شده | Cloudflare D1، جدول portfolio_ledgers | دفتر کامل برای ورود Google؛ دریافت‌های قبلی ChatGPT جدا حفظ می‌شوند |

دو دیتابیس سرور دو استقرار مستقل‌اند؛ اطلاعات خودکار بین D1 و سرور شخصی SQLite جابه‌جا نمی‌شود. هنگام انتقال به سرور خودت، JSON را از «تجمیع» خروجی و در استقرار جدید وارد کن.

## دیتابیس نسخه .NET

فایل پیش‌فرض `data/poolo.db` است. SQL Server یا PostgreSQL لازم نیست. یک سرور شخصی با حجم متعارف داده را با SQLite می‌توان اجرا کرد.

ساختار فعلی عمداً دفتر کاربر را به شکل JSON نگه می‌دارد؛ برای هر سهم یا هر قسط جدول رابطه‌ای جدا ساخته نشده است:

- `Ledgers`: کلید UserId، شماره Revision، وضعیت JSON رکوردها و UpdatedAt. هر رکورد Id، Kind، Version، Deleted و Data دارد.
- `Receipts`: شناسه کاربر + OperationId و محتوای عملیات، برای اینکه تکرار یک درخواست دوباره اعمال نشود.
- `Subscriptions`: اشتراک Web Push هر دستگاه و زبان یادآوری.
- `ReminderReceipts`: جلوگیری از ارسال تکراری یادآوری روزانه.
- `MarketSamples`: قیمت‌های مشاهده‌شده برای نمودارهای بازار.

نوع رکورد جدید `externalSnapshot` است. داده آن شامل سرویس، نام مستعار حساب، نام فهرست، نوع فهرست، زمان دریافت، کامل/ناقص بودن و ردیف‌هاست. مقدارهای پولی و تعداد دارایی به‌صورت رشته اعشاری کنترل‌شده ذخیره می‌شوند تا اعشار رمزارز و تومان آسیب نبیند.

در حال حاضر یک دفتر JSON برای هر کاربر باعث سادگی و اتمیک‌بودن ذخیره می‌شود. محدودیتش این است که هر تغییر، وضعیت دفتر را دوباره می‌نویسد؛ برای سامانه چندکاربره بزرگ یا گزارش‌گیری سنگین بهتر است بعداً دارایی، قسط و منبع به جدول‌های مجزا منتقل شوند. این طراحی CQRS/Event Sourcing کامل نیست.

## معماری .NET

| لایه | نقش |
| --- | --- |
| Domain | قواعد مالی، داده منابع خارجی، کنترل مبلغ، شناسه ردیف و منبع تکراری |
| Application | موارد استفاده همگام‌سازی و PortfolioService؛ قرارداد IFinanceRepository |
| Infrastructure | پیاده‌سازی ذخیره‌سازی با EF Core/SQLite و تراکنش |
| Common | ابزار زمان بر پایه TimeProvider و زمان تهران |
| Web | Controllerهای ASP.NET Core، احراز هویت Google، CSRF، PWA و یادآوری‌ها |

افزونه JavaScript استاندارد Manifest V3 است. رابط PWA هم HTML/CSS و ES Module است. بک‌اند قابل نصب روی سرور خودت .NET 10 است؛ نسخه میزبانی‌شده برای بخش تجمیع یک Worker جدا با D1 دارد.

## جلوگیری از تکرار و خطای هم‌زمانی

هویت یک منبع از سرویس + نام حساب + نام فهرست + نوع فهرست ساخته می‌شود. نام‌گذاری را ثابت نگه دار.

در هر فهرست، هر ردیف کلید پایدار دارد. برای دارایی‌ها، نماد/شناسه منبع؛ برای اقساط، شناسه قسط و در صورت نبود شناسه، عنوان + تاریخ. دو قسط هم‌نام و هم‌تاریخ بدون شناسه یکتا رد می‌شوند تا یکی جای دیگری را نگیرد.

دریافت ناقص ردیف‌های قبلی را نگه می‌دارد؛ زمان مشاهده هر ردیف قدیمی هم حفظ می‌شود. دریافت کامل فقط با انتخاب صریح تو، ردیف‌های غایب همان منبع را کنار می‌گذارد. اطلاعات قدیمی‌تر نمی‌تواند اطلاعات جدیدتر همان فهرست را جایگزین کند.

هر تغییر OperationId یکتا و ExpectedVersion دارد. .NET داخل تراکنش ذخیره می‌کند و Revision توکن هم‌زمانی است. نسخه D1 با UPDATE شرطی روی Revision می‌نویسد. در تداخل، پاسخ 409 داده می‌شود و نسخه محلی حفظ می‌شود؛ برنامه بی‌خبر «آخرین نویسنده برنده است» اجرا نمی‌کند. برای بازیابی، ابتدا JSON محلی را خروجی بگیر، نسخه سرور را بارگذاری و فایل مناسب را دوباره وارد کن.

## معنی اعداد

ارزش ثبت‌شده، جمع ارزش‌هایی است که واقعاً در ردیف‌های واردشده وجود داشته‌اند. مقدار نامشخص صفر فرض نمی‌شود؛ تعداد دارایی بدون ارزش‌گذاری جدا نشان داده می‌شود. مبلغ اقساط پرداخت‌نشده، اقساط با وضعیت «نامشخص» و «پرداخت‌شده» را شامل نمی‌شود.

این اطلاعات Snapshot هستند، نه موجودی لحظه‌ای. یک دارایی مشترک ممکن است در دو کارگزاری دیده شود؛ نسخه اضافه را خودت از جمع حذف کن. جمع این بخش عمداً به موجودی دفتر حساب‌های دستی اضافه نمی‌شود تا دوباره‌شماری رخ ندهد.

در سرور .NET و پس از فعال‌کردن اعلان‌ها، اقساط واردشده با تاریخ مشخص و وضعیت صریح پرداخت‌نشده نیز در یادآوری‌ها بررسی می‌شوند. نسخه D1 میزبانی‌شده فعلاً job یادآوری اقساط واردشده ندارد.

## ورود و حفاظت داده

در سرور خودت، Google فقط هویت کاربر را مشخص می‌کند؛ اطلاعات در Google Drive ذخیره نمی‌شود. روی نسخه میزبانی‌شده، هویت ChatGPT برای بخش تجمیع استفاده می‌شود. رمز، OTP و کوکی حساب‌های مالی به «دمِ دست» منتقل نمی‌شوند.

رمزگذاری سرتاسری برای خلاصه دارایی‌ها در این نسخه وجود ندارد؛ SQLite و JSON محلی نیز خودکار رمزگذاری اختصاصی نمی‌شوند. دسترسی اپلیکیشن با حساب کاربری، جداسازی کاربر و کنترل CSRF محدود شده است. داده استخراج‌شده در سرور مقصدی که خودت برای PWA انتخاب می‌کنی ذخیره می‌شود.

حذف یک منبع در PWA نرم است؛ برای هماهنگی بین دستگاه‌ها نسخه حذف‌شده و رسید عملیات ممکن است در دیتابیس بمانند. فعلاً صفحه پاکسازی دائمی یا آرشیو کامل تاریخچه تغییر دارایی‌ها نداریم.

## اجرا و نگهداری

با .NET 10، دستور `dotnet run --project src/Poolo.Web --environment Development` را در ریشه پروژه اجرا کن. راه‌اندازی Docker، HTTPS و Google در README اصلی توضیح داده شده است. برای همگام‌سازی گوشی و کامپیوتر از همان دامنه HTTPS و همان حساب استفاده کن.

در Docker، پوشه `/app/data` باید volume پایدار باشد. برای پشتیبان‌گیری، برنامه را متوقف یا از سازوکار backup امن SQLite استفاده کن؛ کپی زنده فایل DB به‌تنهایی ممکن است تغییرات WAL را نداشته باشد. کل پوشه data شامل کلیدهای Data Protection و Push نیز برای بازیابی همان نصب مهم است.

خواندن از حساب واقعی پنج سرویس هنوز بررسی نشده است. تست‌ها قواعد داده، نمونه جدول‌های مصنوعی، تراکنش/هم‌زمانی/تفکیک کاربران و مسیر ورود دستی جدول به PWA را پوشش می‌دهند؛ قرارداد API خصوصی یا دسترسی دائمی به تمام سایت‌ها ساخته نشده است.
