# ورود گوگل، دست‌نوشته و سود و زیان

## وضعیت ورود واقعی گوگل

پیاده‌سازی ورود و خروج، همگام‌سازی دفتر، اعتبارسنجی، جداسازی کاربران و تشخیص نبود تنظیمات انجام شده است. **Client ID و Client Secret واقعی این پروژه هنوز ارائه و تنظیم نشده‌اند؛ بنابراین ورود با حساب واقعی گوگل فعلاً فعال و آزمایش نشده است.** تست‌ها از پاسخ‌های مصنوعی گوگل استفاده می‌کنند، نه حساب Gmail واقعی. رمز Gmail لازم نیست و ایمیل‌ها خوانده نمی‌شوند.

برای فعال‌کردن:

1. در [Google Cloud](https://console.cloud.google.com/auth/clients) یک پروژه انتخاب کن و OAuth consent screen را تنظیم کن. برای استفاده شخصی، در حالت Testing حسابت را به Test users اضافه کن.
2. OAuth Client از نوع **Web application** بساز.
3. آدرس Authorized redirect URI را دقیقاً برابر آدرس برنامه + `/signin-google` بگذار؛ برای نمونه:
   - نسخه خصوصی فعلی: `https://poolo-finance.sahar-tarkha-0855.chatgpt.site/signin-google`
   - اجرای محلی: `http://localhost:5000/signin-google`
4. Client ID و Client Secret را در تنظیمات سرور نگه دار. آنها را داخل فایل JavaScript، سورس عمومی یا پیام یادداشت وارد نکن.
5. برنامه را دوباره اجرا/منتشر کن. در **Settings → Google sign-in setup** باید وضعیت آماده ورود دیده شود. سپس Sign in را بزن. برای هماهنگی دستگاه‌ها از همان URL و همان حساب استفاده کن.

### اجرای محلی .NET در ویندوز

از ریشه پروژه اجرا کن:

```powershell
.\scripts\setup-google.ps1
```

اسکریپت Client ID را می‌گیرد و Client Secret را به شکل مخفی می‌پرسد. تنظیمات را از stdin به `dotnet user-secrets` می‌دهد تا Secret در آرگومان خط فرمان نباشد. User Secrets ابزار توسعه محلی است و فایل آن رمزگذاری اختصاصی ندارد. برنامه را در Development دوباره اجرا کن:

```powershell
dotnet run --project src/Poolo.Web --urls http://localhost:5000 --environment Development
```

### سرور شخصی .NET

`Authentication__Google__ClientId` و `Authentication__Google__ClientSecret` را روی سرور تنظیم کن. در Docker همان GOOGLE_CLIENT_ID و GOOGLE_CLIENT_SECRET فایل .env استفاده می‌شوند. کوکی و کلیدهای Data Protection باید ماندگار باشند؛ تنظیم reverse proxy و HTTPS README همچنان لازم است. `.NET` از middleware رسمی AddGoogle با PKCE، state/correlation، کوکی HttpOnly و CSRF استفاده می‌کند و توکن گوگل را در دفتر مالی نگه نمی‌دارد.

### نسخه خصوصی میزبانی‌شده

در runtime secrets این نسخه، `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` را ثبت کن؛ کلید تصادفی مستقل `GOOGLE_AUTH_SECRET` هم برای state لازم است. کلید امضای داخلی در محیط این نسخه تنظیم می‌شود؛ دو کلید گوگل باید از پروژه خودت بیایند. تغییردادن secret نیاز به انتشار نسخه دارد. مسیر OAuth در Worker مستقل است و .NET روی این میزبان اجرا نمی‌شود.

ورود سایت خصوصی با ChatGPT همچنان مرز دسترسی سایت است. ورود Google داخل برنامه، دفتر شخصی مالی را به شناسه Google متصل می‌کند. دریافت‌های قدیمی افزونه با هویت ChatGPT حذف نمی‌شوند؛ پس از ورود Google، در «تجمیع» دکمه **Import previous captures** را بزن و ورود اطلاعات را تأیید کن. این جابه‌جایی خودکار نیست.

نسخه Worker از authorization code، PKCE، state امضاشده وابسته به مرورگر و مالک سایت، مهلت ۱۰ دقیقه و مصرف یک‌باره state استفاده می‌کند. هویت از endpoint رسمی UserInfo و ایمیل تأییدشده دریافت می‌شود. نشست opaque تصادفی، HttpOnly/Secure/SameSite=Lax است؛ فقط هش شناسه نشست در D1 می‌ماند. scopeها فقط openid/email/profile هستند. اطلاعات ورود گوگل در حافظه موقت برای تکمیل ورود مصرف می‌شوند و access/refresh token ذخیره نمی‌شوند. خروج، نشست همان دستگاه را با کنترل Origin و CSRF باطل می‌کند.

در حالت ورود Google، تمام دفتر شامل یادداشت، طراحی، دارایی و دریافت‌های افزونه در `finance_ledgers` D1 ذخیره می‌شود. رسید عملیات در همان وضعیت و همان UPDATE شرطی Revision ثبت می‌شود؛ batch اتمیک است و پاسخ 409 تعارض را نشان می‌دهد. رسیدها برای صرفه‌جویی بی‌خبر حذف نمی‌شوند. جدول قدیمی `portfolio_ledgers` برای دریافت‌های قبلی ChatGPT حفظ شده است. جدول‌های `google_sessions` و `google_oauth_uses` نشست و state را نگه می‌دارند. Migration جدید فقط جدول/ایندکس اضافه می‌کند و اطلاعات قبلی را پاک نمی‌کند. Worker هنوز زمان‌بند Push شخصی ندارد؛ اعلان بسته‌بودن برنامه نیازمند سرور .NET است.

منابع: [راهنمای رسمی Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server)، [Google login در ASP.NET](https://learn.microsoft.com/aspnet/core/security/authentication/social/google-logins?view=aspnetcore-10.0).

## دفتر دست‌نوشته

در **Notes / Planner → Handwritten notes** یک صفحه تازه بساز یا روی پیش‌نمایش یک یادداشت بزن. برای یادداشت متنیِ موجود، دکمه «افزودن طراحی» همان یادداشت را به صفحه طراحی وصل می‌کند. ابزارها: قلم، هایلایتر، پاک‌کن مسیر، انتخاب/جابه‌جایی، حرکت صفحه، خط، پیکان، مستطیل، بیضی و متن. ضخامت و رنگ انتخاب می‌شوند؛ Undo/Redo تا ۳۰ تغییر، Zoom و خروجی SVG وجود دارد. قلم دستگاه، ماوس و لمس پشتیبانی می‌شوند؛ با Stylus only لمس انگشت برای نوشتن نادیده گرفته می‌شود. این صفحه یک تخته طراحی داخلی الهام‌گرفته از تجربه Excalidraw است؛ وابسته به سرویس Excalidraw نیست و فایل آن سرویس را Import نمی‌کند. PDF annotation، دفتر چندصفحه‌ای Flexcil و تشخیص دست‌خط جزو این نسخه نیستند.

طراحی، داده برداری در فیلد اختیاری Drawing همان PersonalNote است. متن و چک‌لیست یادداشت حفظ می‌شوند. Save & close همان note را با نسخه رکورد در صف IndexedDB می‌گذارد و پس از ورود، با دفتر همگام می‌کند. پیش‌نویس بعد از تغییر روی همان دستگاه نگه داشته می‌شود؛ بازیابی آن فقط وقتی نسخه مبنا هنوز برابر نسخه یادداشت باشد انجام می‌شود. پیش‌نویس تا زدن Save بین دستگاه‌ها همگام نمی‌شود. به‌روزرسانی متن از کلاینت قدیمی که Drawing را نمی‌شناسد، طراحی را بی‌خبر پاک نمی‌کند.

حدود: صفحه ۳۲۰ تا ۸۰۰۰ واحد، ۵۰۰ عنصر، ۲۰ هزار نقطه و حداکثر ۷۵۰ کیلوبایت برای یک یادداشت. ورودی هندسی، رنگ، متن و شناسه اعتبارسنجی می‌شود؛ متن در SVG escape می‌شود و URL خارجی در رنگ/عنصر مجاز نیست. درخواست همگام‌سازی دفتر حداکثر یک مگابایت است؛ صف، تعداد و حجم UTF-8 را با هم محدود می‌کند.

## دارایی، قیمت روز و سود/زیان

در **Investing → Asset performance → New asset** نوع دارایی را انتخاب و مقدار را وارد کن. نام از نوع انتخابی پر می‌شود. مثلاً GOLD یعنی گرم طلای ۱۸ عیار؛ GOLD24 یعنی گرم ۲۴ عیار، COPPER بر حسب تن و ارز/رمزارز به ازای یک واحد است. واحد کنار مقدار و قیمت نمایش داده می‌شود. قیمت فعلی از همان API بازار می‌آید و ارزش = مقدار × قیمت واحد محاسبه می‌شود. برای رمزارزِ با نرخ دلار، قیمت و نرخ دلار هر دو لازم‌اند و تبدیل به تومان یک‌بار انجام می‌شود. قیمت داخلی TGJU و قیمت پایانی TSETMC قبلاً در adapter به تومان تبدیل شده‌اند.

**بهای خرید اختیاری است.** بدون آن ارزش فعلی دیده می‌شود و سود/زیان نامشخص می‌ماند. برای دیدن سود، بهای کل خرید شامل کارمزد و تاریخ خرید را ثبت کن. چند خرید با مقدار و تاریخ جدا قابل ثبت است. فقط خریدهای باز، یعنی مقداری که هنوز نگه داشته‌ای، وارد کن. فروش و سود تقسیمی/نقدی در این مدل محاسبه نمی‌شوند؛ سود نمایش‌داده‌شده محقق‌نشده است.

دارایی‌های واردشده از افزونه و دارایی‌های بلوکه هم در فهرست دیده می‌شوند. برای هر کدام بهای خرید ثبت کن و در صورت نیاز آن را به نماد بازار وصل کن. اگر مقدار فعلی واردشده با جمع خریدهای ثبت‌شده برابر نباشد، سود تا اصلاح خریدها مخفی می‌ماند. بهای نامشخص صفر فرض نمی‌شود. ارزش‌گذاری قدیمی‌تر از آخرین خرید، مبنای سود فعلی قرار نمی‌گیرد. منبع یا تاریخ نامشخص با برچسب خودش نمایش داده می‌شود. مجموع فهرست ممکن است به دلیل دریافت یک دارایی مشترک از دو منبع هم‌پوشانی داشته باشد؛ منبع تکراری را خودت حذف کن.

نمودار روزانه/هفتگی/ماهانه از داده‌های واقعی موجود، بعد از تاریخ خرید، ساخته می‌شود. قیمت دلاری تاریخی فقط با نرخ دلار همان روز مقایسه می‌شود؛ روزِ بدون یکی از دو نرخ حذف می‌شود. برای دارایی بدون API یا NAV ناموجود می‌توان ارزش کل را در تاریخ‌های مشخص دستی وارد کرد. هر سطر: `1405/08/25, 12,000,000`. نمودارها قیمت‌های خام و تعدیل‌نشده بورس را نشان می‌دهند؛ افزایش سرمایه و سود تقسیمی باید در داده خرید/ارزش‌گذاری منعکس شوند. قیمت و سودِ پیش از شروع داده واقعی ساخته نمی‌شود.

## عددها و معماری

بخش صحیح ورودی‌های مالی/مقدار، سه‌رقمی جدا می‌شود؛ علامت، مکان نشانگر، اعشار و صفرهای اعشاری حفظ می‌شوند. ارقام فارسی/عربی و جداکننده‌های `,`، `٬` و `٫` در ورود پذیرفته می‌شوند و قبل از ذخیره به عدد استاندارد تبدیل می‌شوند. مقدار رمزارز تا ۱۸ رقم اعشار به‌صورت رشته نگه داشته می‌شود؛ پول محاسباتی در کلاینت با BigInt در مقیاس صدم تومان است. تاریخ‌ها و شناسه‌ها جداکنندهٔ مبلغ نمی‌گیرند.

مدل‌های Drawing و Assets در Domain، قرارداد IAssetPerformanceService در Application/Interfaces/Assets، سرویس در Application/Services و Query/Controller اختصاصی در Features/Assets و Web/Controllers قرار دارند. مسیر `/api/assets/{id}/performance` خلاصه سود از ارزش‌گذاری‌های دستی ثبت‌شده را برمی‌گرداند؛ ارزش‌گذاری خودکار و نمودار PWA از API قیمت‌های بازار استفاده می‌کنند. نسخه .NET همچنان EF Core/SQLite با همان مدل دفتر JSON است؛ افزودن Drawing و assetPosition به Migration دیتابیس .NET نیاز ندارد.
